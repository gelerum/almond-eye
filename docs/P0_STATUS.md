Новые версии, часовой пояс, включительная конечная дата и неизменность истории проверены через API с временной БД.

## Принятые технические решения

FastAPI + Pydantic + SQLAlchemy, локальная SQLite и статический интерфейс для первой итерации. SQLite и JS без React — временное упрощение запуска, явно отличающееся от целевой архитектуры. Весь импорт подтверждается после серверной проверки, документы сохраняются атомарно; режим фиктивных детекций вынесен в отдельный endpoint. Реальный `/evaluations/analyze` использует отдельный optional-адаптер Ultralytics и возвращает `503`, пока веса не настроены; fake-детектор допускается только в тесте через инъекцию.

Следующий этап по плану: разметить и разделить реальные сцены, выбрать модель с нужными классами, подключить её через отдельный worker и довести реальную цепочку «снимок → рамки → правило → предупреждение».

## Продолжение после пользовательских изменений

Сохранены добавленные пользователем пакетная загрузка, optional-адаптер модели, advisory-классификатор этапов и скрипт его обучения. Исправлены обработка хеш-имён снимков без расширений, ложное объявление классов поддержанными, обработка неверных весов/mapping, идентификация версии весов и ошибки inference. Классы, присутствующие в весах, отделены от проверенных на выборке; список проверенных по умолчанию пуст. Для обоих адаптеров используется декодированное изображение, ошибки возвращаются без создания предупреждения об отсутствии.

Добавлены UI запуска анализа, статусы готовности, просмотр снимка с рамками и полигоном из сохранённого результата, фильтры последних 50 проверок, подписи демонстрационных и фиктивных данных, ошибки пакетной загрузки по файлам. Уточнено, что `10.1` — номер раздела; календарных дат в исходном Excel нет.

Проверка: pytest и отдельные Node-тесты рендеринга доказательств; тесты адаптеров используют doubles без скачивания весов и не являются оценкой качества распознавания. Веса реальной модели по-прежнему не предоставлены. Браузерный прогон новых экранов в этой итерации не выполнен.
