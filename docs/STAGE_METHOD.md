# Методика «этап ← почерк техники» и сравнение с планом

> Цифры пересчитываются командами `uv run --no-sync python scripts/eval_stage_inference.py` и
> `uv run --no-sync python scripts/seed_demo.py --ground-truth --timeline --database sqlite:///runtime/gt.db`.
> Данные на 28.09.2026.

## 1. Определение этапа по кадру (`backend/app/domain/stage_inference.py`)

Правила лежат в `backend/app/rules/stage_signatures.yaml`: у каждого этапа есть название, порядок, OR-группы
`required`, веса `supporting` и `contradicting`, а также `allowed`, `pace_critical`, `completed_by` и
`plan_keywords`. У каждой строки есть комментарий с обоснованием.

Присутствие признака `p(x)` берётся из уверенности детектора. Для материалов используется максимум из уверенности и отношения
`доля кадра / 0.10`.

```
score = 0.6 · (средняя закрытость required-групп) + Σ w·p(supporting) − Σ w·p(contradicting),  обрезка в [0, 1]
```

- Полный почерк даёт 0.6–0.95. Например, экскаватор с самосвалом дают 0.90, одиночный экскаватор — 0.60.
- Если лучший счёт ниже `min_score = 0.3`, первым в списке идёт `unknown` («сочетание не соответствует ни одному этапу»).
- При ничьей выше ставится этап с полным почерком, затем более ранний этап. В сомнении прогресс не приписывается.
- К каждому этапу прилагается объяснение, например: «вижу экскаватор и самосвал; нет буровых установок → разработка
  котлована, уверенность 0.90».
- Этапы `interior` (лифты, отделка) и `commissioning` (ввод) помечены `observable: false`: с камер площадки
  их не видно, и по снимкам они не оцениваются.

### Точность на 100 размеченных кадрах

| Вход | top-1 | top-2 |
|---|---|---|
| Эталонная разметка техники (потолок методики) | **0.74** | **0.84** |
| Ансамбль детекторов (кэш `runtime/eval/raw.json`, текущие пороги слияния) | 0.36 | 0.52 |

Точность по этапам при эталонной разметке: сваи 38/40, котлован 27/34, надземная часть 3/3, подготовка 3/8,
подземная часть 2/9, фундамент 1/5.

Основные ошибки видны по самим данным:

- **Котлован ↔ сваи (6 кадров).** В переходный месяц буровые ещё стоят, а экскаватор уже копает. Разметчик
  ставит «котлован», методика — «сваи», потому что буровая сильнее. Правильный ответ почти всегда второй в списке.
- **Подготовка ↔ котлован (5).** Одиночный экскаватор на подготовке неотличим от котлована.
- **Подземная часть ↔ котлован (5).** Экскаватор с башенным краном без видимого бетона. Материалы
  (опалубка, арматура) в эталонной разметке отсутствуют, а детекторы материалов должны закрыть этот случай.

Веса подбирались вручную на этих же кадрах, но каждое правило остаётся инженерно объяснимым: мы не
подгоняли его под отдельный кадр. Например, мы отказались от правила «погрузчик = благоустройство», которое
давало +1 кадр, и приняли −1 кадр, лишь бы одиночный погрузчик во время свай не превращался в «благоустройство».

Для детекторов главная потеря — сваи (0 из 40). Grounding DINO находит буровые установки (63 бокса в кэше),
но после слияния они почти не доходят до выхода: их вытесняет `mobile_crane` в группе конфликтов кранов или
отсекает порог. Это вопрос настройки ансамбля (`backend/app/config/detectors.yaml`), а не методики.

## 2. Сравнение с планом (`backend/app/domain/progress.py`)

Для даты D берутся все снимки объекта с датой ≤ D. Снимок служит доказательством этапа, если score ≥ 0.5.

- **Отсев одиночных срабатываний.** Эпизод этапа — это подряд идущие даты съёмки, на которых виден этап. Эпизод из одной даты, который не
  подтвердила следующая съёмка, считается шумом (`ignored_image_ids`). Пример: экскаватор на подготовке
  площадки B 24.01.2024. Последний эпизод сохраняется всегда: у него ещё не было шанса подтвердиться.
- **Окно и допуск.** Окно свежести — 45 дней, так как снимки ежемесячные. Допуск по срокам — 7 дней: меньшие расхождения не считаются
  отставанием или опережением.

| Ситуация | Статус этапа |
|---|---|
| план закончен, этап всё ещё виден на последней съёмке | `behind`, N = последнее наблюдение − окончание |
| план закончен, этап больше не виден | `done`; задержка сохраняется в `delay_days`, но в вердикт не идёт |
| план идёт или закончен, этап не виден, на свежих кадрах только предыдущие этапы | `behind`, N = D − плановое начало |
| этап виден раньше планового начала | `ahead`, `delay_days` = −N |
| идёт, но на его последних кадрах нет ни одной `pace_critical` машины | `at_risk` + алерт `pace_risk` |
| в кадре стоит признак `completed_by` (башенный кран для «Установки башенного крана») | `done` |
| нет кадров за 45 дней | `no_data` (и вердикт `no_data`) |

- **Техника не по этапу.** На свежих кадрах ищется техника, которой нет среди признаков ни одного активного по плану
  этапа и ни одного распознанного на этом кадре этапа плана. Общая техника (грузовик, манипулятор, автокран)
  допускается всегда.
- **Проверенные классы.** Отсутствие машины (`pace_risk`) сообщается, только если класс входит в `supported_classes`
  всех использованных анализов, то есть в `validated_classes` детектора.
- **Вердикт.** Выбирается худший статус в порядке `behind` > `at_risk` > `ahead` > `on_track`. Для `behind` берётся максимальная
  задержка. Этапы `done`, `not_started` и ненаблюдаемые в вердикт не входят.

## 3. Демо-планы (`scripts/make_demo_plans.py` → `data/plans/<site>.xlsx`)

Формат повторяет шаблон организатора:

- заголовок «График производства работ» и строка объекта;
- строка лет и строка месяцев;
- залитые ячейки месяцев на плановый интервал;
- столбцы «Начало» и «Окончание» с точными датами;
- скрытый столбец «Ключ этапа».

Этапы идут по шаблону и перечню ЛТЦ до «Ввода объекта». Реальных графиков у нас нет, поэтому даты подобраны
так, чтобы честно вычисленные исходы на дату последнего снимка различались:

| Площадка | Задуманный сценарий |
|---|---|
| A | хроническое отставание: сваи +45 дней к 14.08.2023, надземная часть не закончена к 09.08.2024 |
| B | демо слайда 8: котлован затянулся, экскаватор без самосвалов, фундамент не начат |
| C | котлован в графике, но без самосвалов: риск снижения темпа |
| D | в графике: сваи и котлован закончены в срок, идёт монтаж башенного крана |
| E | опережение: сваи и котлован начаты раньше плана |

## 5. Ограничения

- Пять планов составлены нами, а точность методики измерена на тех же 100 кадрах, на которых подбирались веса.
  Независимой проверочной выборки нет.
- Один кадр в месяц: отставание измеряется с точностью до интервала между съёмками. На первой дате серии
  одиночное срабатывание ещё нельзя отсеять (площадка B, 24.01.2024).
- Правило «видны только предыдущие этапы → старт задерживается» строгое. Этапы, которые идут параллельно и не видны
  с камеры, дадут ложное отставание. Поэтому в планы стоит включать только наблюдаемые этапы или помечать
  остальные как `observable: false`.
- Демонтаж башенного крана распознаётся только при видимых материалах готового здания (леса, кладка). Иначе его
  нельзя отличить от монтажа.
