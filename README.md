# Контур: мониторинг строительных площадок

Первая рабочая итерация P0 из [плана](IMPLEMENTATION_PLAN.md). Это основа приложения, **не завершённая P0**: подключена Construction Hazard Detection, реализованы адаптер и интерфейс анализа; отдельного worker, разметки и измерений качества на целевой выборке пока нет.

## Обновление 23.09: отдельные сроки и обзор сцены

Основной график теперь загружается отдельно от перечня работ по нашему шаблону CSV. В разделе «График и источники» скачайте шаблон, заполните даты, выберите календарь, проверьте ошибки и сохраните новую версию. Производительность и объём для этого не нужны. Расчёт сроков остаётся необязательным демонстрационным примером.

Анализ кадра доступен без графика, зоны и времени съёмки. Он сохраняет обзор людей, техники, транспорта, СИЗ и конусов, кандидатов на проверку СИЗ и, при наличии дат и зоны, календарный контекст. Проверка состава техники отображается отдельно и по-прежнему требует модели нужных классов. Общие классы дают полезные наблюдения, но не подтверждают конкретные типы техники или выполнение работ.

Формат, сценарии, ограничения и план развития: [Отдельные сроки и обзор кадра](docs/TIMELINE_AND_SCENE.md). Актуальные проверки: 42 Python-теста, 5 Node-тестов; реальный прогон трёх снимков — `data/manifests/scene-smoke.json`.

## Construction Hazard Detection

Подключён компактный **YOLO11n** из [репозитория автора](https://github.com/yihong1120/Construction-Hazard-Detection), веса из [Hugging Face](https://huggingface.co/yihong1120/Construction-Hazard-Detection). Используется зафиксированная ревизия `212ee245136b4e330f84b409f67f3d35eff59f42`, SHA-256 `f55600c106ba7952c64d2aec70dc673240b422bdbd989d395d301b0d5426b02b`. Лицензия модели — AGPL-3.0; её текст скачивается вместе с весами.

Установка и запуск из корня проекта (в текущем окружении зависимости и веса уже установлены):

```powershell
./.venv/Scripts/python.exe -m pip install -r requirements.detector.txt
./.venv/Scripts/python.exe scripts/download_hazard_model.py
./scripts/start_hazard.ps1
```

Открыть http://127.0.0.1:8000 и использовать форму «Проверка снимка» после выбора снимка; график и зона необязательны. Если сервер уже запущен, остановить его и запустить этой командой. Для других способов запуска задайте `DETECTOR_PROFILE=construction-hazard`; стандартный путь весов выбирается автоматически, `DETECTOR_MODEL` позволяет его переопределить. Обычный запуск без профиля сохраняет прежний режим настраиваемого детектора.

Скачанные веса YOLO11n содержат 10 исходных классов: каска, маска, отсутствие каски/маски/жилета, человек, конус, жилет, техника и транспорт. В общей документации автора указано 11 классов, но `utility pole` в этих весах отсутствует; `/api/health` показывает фактические классы. Профиль также принимает новый набор из 11 классов. Все рамки с confidence >= 0.25 сохраняются в `observation.model_detections` и отображаются в истории с русскими подписями. Слабые кандидаты не являются подтверждёнными нарушениями. Модель не различает восемь типов техники проекта: `machinery` **не означает** экскаватор, `vehicle` **не означает** самосвал. Поэтому профиль не принимает `DETECTOR_CLASS_MAP`, не заполняет детекции конкретной техники и оставляет результат проверки графика «недостаточно данных». Обнаружение объектов подключено; алгоритмы автора для расстояний, трекинга и зон по конусам не перенесены.

Воспроизводимая проверка реального inference через API, с временной БД и без изменения пользовательской истории:

```powershell
./.venv/Scripts/python.exe -X utf8 scripts/check_hazard_model.py Строительная_техника/Screenshot_1.png Строительная_техника/Screenshot_26.png Строительная_техника/Screenshot_50.png
```

Отчёт: `data/manifests/hazard-smoke.json`. Это проверка запуска, нормализованных рамок и сохранения результатов, а не измерение точности: независимой разметки нет.

## Запуск на Windows

Требуется Python 3.12. Из корня проекта:

```powershell
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements.lock.txt
./.venv/Scripts/python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

Открыть http://127.0.0.1:8000. Контракты API: http://127.0.0.1:8000/docs.

Linux/macOS: те же команды с `.venv/bin/python` вместо `./.venv/Scripts/python.exe`.

## Что работает

- Площадки с часовым поясом, камеры, версии полигонов зон; проверка принадлежности одной площадке.
- Импорт CSV UTF-8/XLSX: выбор листа, столбцов и строки заголовков, предпросмотр, исходные значения, нормализация номеров разделов (например, `10.1`), которые Excel хранит в формате даты, ошибки иерархии/дат/дублей, атомарное сохранение версии.
- Реестр внешних источников; демонстрационный расчёт по объёму и выработке. API поддерживает зависимости, параллельные работы, рабочую неделю, исключаемые даты и календарные выдержки после предшественников. UI пока рассчитывает одну выбранную работу.
- Сохранение версий графика с параметрами, формулой и происхождением сроков. Без даты привязки получается относительный график.
- Загрузка одного или пакета PNG/JPEG с камерой, временем и его источником, хешем, проверкой декодирования, размеров и яркости; ошибка одного файла не отменяет сохранение остальных; просмотр исходников.
- Ядро проверки одного кадра: зона по нижнему центру рамки, группы альтернатив, обязательная техника, объединение допустимых классов параллельных этапов, отдельное «недостаточно данных».
- Тестовый API проверки `/evaluations/fixture`, история и объяснения. **Детекции передаются явно и сохраняются с `mode=fixture`; это не распознавание изображения.** Время берётся из сохранённого снимка. Низкое качество и отсутствие подтверждённого покрытия блокируют предупреждения.
- Повтор одинакового импорта, расчёта или проверки возвращает ту же запись; новая конфигурация создаёт новую версию. Предыдущий результат содержит снимок конфигурации.

## Сценарий в интерфейсе

1. Создать площадку и камеру; задать полигон зоны в координатах 0–1. Покрытие подтверждать только после проверки контрольного кадра.
2. Загрузить исходный Excel: заголовки в строке 3, номер в столбце 1, название в столбце 2. Просмотреть 19 восстановленных номеров и 250 предложенных родителей; подтвердить сохранение.
3. Выбрать работу «Выемка грунта котлована» (строка 72), зону и проверить источник. Не назначать этот шаблон произвольной работе. Уточнить параметры демонстрационного расчёта, проверить предпросмотр и сохранить версию.
4. Загрузить снимок. При неизвестном времени оставить пустым; при назначении даты для примера выбрать демонстрационный источник времени. При настроенных весах выберите снимок, версию графика и зону этой камеры в форме «Проверка снимка». Запустите анализ и откройте карточку в истории. Без весов кнопка недоступна.

Общий класс «грузовик» никогда не заменяет «самосвал». Часовой пояс снимка обязателен при вводе времени. Конечная дата графика включительна в часовом поясе площадки. Учитываются целые рабочие дни; почасовые смены пока отсутствуют.

## Хранение и ограничения

Сейчас SQLAlchemy + локальная SQLite, файлы в `runtime/images/`. `DATABASE_URL` и `RUNTIME_DIR` переопределяют расположение. Для PostgreSQL требуется драйвер `psycopg[binary]`; этот вариант пока не проверен. Схема создаётся при запуске; последующие изменения схемы потребуют миграций. В БД проекты и неизменяемые документы с типом, версией, внешними ссылками, JSON-контрактом и уникальным ключом содержимого. Проверка связей документов выполняется в API.

UI первой итерации — HTML/CSS/JavaScript без сборки. Эти временные отступления от React/PostgreSQL в плане сокращают подготовку первого запуска; доменная логика отделена от UI и хранения. Не объявляем эту структуру завершённой архитектурой P0.

Приложение предназначено для локального запуска на `127.0.0.1`: авторизации, защиты публичного API и производственной обработки больших пакетов ещё нет. Не публиковать текущую сборку в интернет.

Для пакетной загрузки через API используйте `POST /api/projects/{project_id}/images/batch`: поле `files` повторяется для снимков, а `manifest` содержит JSON-объект с именами файлов и полями `captured_at`/`time_source`. Форма интерфейса использует этот маршрут автоматически при выборе нескольких файлов.

Реальный анализ включается отдельно после установки `pip install -e ".[detector]"` и задания `DETECTOR_MODEL` на веса детектора. Для пользовательских имён классов задайте `DETECTOR_CLASS_MAP` как JSON mapping, например `{"excavator":"excavator","dump_truck":"dump_truck"}`. После загрузки снимка вызовите `POST /api/projects/{project_id}/evaluations/analyze` с `image_id`, `schedule_id` и `zone_id`. Без весов endpoint возвращает `503`, а fixture-режим остаётся отдельным тестовым контуром.

Проверка готовых моделей зафиксирована в [реестре исследования](data/manifests/model-research.json). Готовой модели этапов, совместимой с перечнем работ проекта и имеющей проверяемую лицензию, не найдено. Для собственной модели используйте датасет в формате `dataset/{train,val,test}/{stage_label}/*.jpg` и `scripts/train_stage_model.py`; после обучения задайте `STAGE_MODEL`. Endpoint `POST /api/projects/{project_id}/images/{image_id}/stage-prediction` возвращает только advisory-предсказание и не меняет выбор активного этапа графика.

Далее: проверка и ручная корректировка сопоставлений, разметка сцен и независимого тестового набора, реальный детектор и отдельный worker, рисование зон на снимке, серверная фильтрация и пагинация всей истории, оценка неопределённости сроков, PostgreSQL/Alembic и Docker Compose. Статус каждого пункта — в [документе прогресса](docs/P0_STATUS.md).

## Продолжение P0: анализ и доказательства

Исходный Excel содержит номера разделов работ, **календарных дат в нём нет**. Некоторые ячейки с номерами Excel технически хранит в формате даты; импорт возвращает их к виду `10.1`, `12.3` и не назначает из них сроки.

- В интерфейсе есть готовность модели, выбор снимка/версии графика/зоны, запуск анализа и отображение ошибок.
- Карточка результата накладывает рамки и сохранённый полигон зоны на исходный снимок. Смена текущей конфигурации не меняет доказательства старой проверки. Все рамки показаны независимо от их участия в выводе. Экспериментальные и тестовые данные обозначены явно.
- Статусы и режим можно отфильтровать в последних 50 загруженных результатах. Это пока не поиск по всей истории.
- В пакетах допускается до 100 файлов с уникальными именами. Ошибки отдельных файлов видны в интерфейсе.
- Адаптер передаёт модели декодированный PIL-снимок: хранилище использует имена SHA-256 без расширений. Ошибка модели не записывается как отсутствие техники.

### Поддержка классов

`DETECTOR_CLASS_MAP` сопоставляет **фактические названия в весах** внутреннему словарю. Наличие класса в mapping не делает его поддержанным. По умолчанию `DETECTOR_VALIDATED_CLASSES=[]`: можно видеть реальные рамки, но проверки обязательной техники дают «недостаточно данных».

После проверки модели на независимой выборке укажите только проверенные классы:

```powershell
$env:DETECTOR_MODEL = 'C:/path/to/verified-model.pt'
$env:DETECTOR_CLASS_MAP = '{"excavator":"excavator","dump_truck":"dump_truck"}'
$env:DETECTOR_VALIDATED_CLASSES = '["excavator","dump_truck"]'
```

Это конфигурация оператора после измерений, а не автоматическая сертификация качества. Если проверенный класс отсутствует в весах, загрузка отклоняется. `GET /api/health` различает `available_classes` и `supported_classes`. Версия детектора зависит от SHA-256 весов, mapping, списка проверенных классов и параметров inference. Замена файла под тем же именем создаёт другую версию.

Для обычного профиля вызов `predict` использует CPU, conf=0.01, iou=0.7, imgsz=640 и max_det=300. Низкий порог сохраняет слабые кандидаты для проверки неопределённости; порог решения задаётся правилом. Правило с порогом ниже 0.01 блокируется состоянием «недостаточно данных». Достижение лимита 300 рамок считается неполным результатом и ошибкой анализа. Контракт PIL/Results и параметры сверены с [официальной документацией Ultralytics](https://docs.ultralytics.com/modes/predict/).

API по-прежнему выполняет анализ синхронно. Пока отдельный worker не реализован, интерфейс показывает ожидание завершения HTTP-запроса. Запросы к одной модели сериализуются для предотвращения одновременного изменения её внутреннего состояния.
